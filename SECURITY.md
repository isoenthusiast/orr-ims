# Security, privacy and reporting

This candidate is documentation with a local static brand preview and a Python
asset builder. No hosted IMS, user database, telemetry or production service is
provided. No supported production versions or response-time commitments exist.

Do not place credentials, client information, real risk/incident records or
personal data in public issues, commits, screenshots or examples. Use synthetic
records. The published personal attribution is Edward Wee's name and LinkedIn
link at his express request.

For a security issue, use GitHub's private vulnerability reporting through the
repository's Security tab when available. For rights concerns or if that route
is unavailable, contact [Edward Wee](https://www.linkedin.com/in/edwardbhwee/)
with a non-sensitive summary to arrange a private channel. Do not send credentials,
client records or sensitive evidence through public issues or LinkedIn messages.

For any later deployment, access controls, audit trails, secure attachments,
backups, retention, recovery and privacy obligations require separate design and
validation. The absence of obvious secrets in this candidate is not proof that
a future system is secure or legally compliant.
