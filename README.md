# ORR IMS — an example integrated management system

**Learn how management-system requirements become everyday work—with connected
procedures, practical templates and a worked example.**

ORR IMS is an open-source example Integrated Management System (IMS) for learners
and people preparing to implement a management system in their organization.
It helps you explore what requirements mean in practice: who does what, how
decisions are made, which records to keep, and how to check whether an action worked.

The intended learning scope brings together quality, environmental, occupational
health and safety, and business continuity management—the areas associated with
ISO 9001, ISO 14001, ISO 45001 and ISO 22301. The library is being developed in
stages; the current draft provides a starting point, not a complete implementation
or a verified interpretation of all four standards.

**New to management systems? Start with the
[Beginner’s Guide](docs/templates/beginner/ORR-SOP-IMP-002_START-AN-IMS-FROM-SCRATCH.md).**

## See how the pieces connect

Imagine a customer changes a product specification. How does that change reach
the people doing the work? Who assesses the risk, approves the new instructions
and checks that both shifts understand them? What happens when a handoff fails?

Follow [Cedar Estuary Blending, our fictional chemical company](docs/templates/beginner/ORR-REC-IMP-001_FICTIONAL-CHEMICAL-COMPANY-JOURNEY.md),
through that journey. The example links context, risks, controls, objectives,
document changes and leadership decisions—and shows why completing an action
is different from proving it was effective.

The learning thread is **Objective → Risk → Control → Assurance (ORCA)**:
know what you want to achieve, understand what could prevent it, define the
control, and examine evidence that it works.

## A starting path for beginners

You do not need prior IMS implementation experience to begin exploring the library.
The [Beginner’s Guide](docs/templates/beginner/ORR-SOP-IMP-002_START-AN-IMS-FROM-SCRATCH.md)
explains how to start from existing work practices, identify the people and inputs
you need, and build a first implementation loop.

1. **Understand the whole system.** Explore the
   [23-process catalogue](docs/templates/beginner/ORR-REG-IMP-001_PROCESS-CATALOGUE.md)
   and see which areas have starter material and which remain to be developed.
2. **Follow a completed example.** Read the fictional company journey to see how
   decisions, actions and evidence link together.
3. **Try the first five kits.** Work through context and scope, risks and controls,
   objectives, document control and management review. Each kit includes a
   procedure and a blank worksheet, with editable Word and Excel editions.
4. **Adapt and check.** Use the
   [acceptance protocol](docs/templates/beginner/ORR-ASP-IMP-001_BEGINNER-KIT-ACCEPTANCE.md)
   to test handoffs, missing inputs and failed controls before organizational adoption.

## Current scope and responsible use

**This is a draft learning library.** Five connected kits cover parts of four
process areas—P01, P04, P08 and P20. The full P01–P23 library and twelve planned
architectural standards are not yet supplied. Two proposed ISO clause mappings
remain unverified; the repository is not a complete conformity checklist.

Use the examples to learn and adapt. Actual implementation needs your organization's
scope, competent people, applicable obligations, technical criteria, approvals and
real operating evidence. Consult the applicable standards through lawful access;
this repository does not replace them or guarantee certification. All worked
company records are fictional. Keep real organizational records private.
